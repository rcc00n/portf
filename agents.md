# RACCN Code

This repository powers RACCN Code and includes both the frontend and backend.

## Goal

Evolve the current website into an exceptional interactive digital experience.

The target quality is comparable to excellent contemporary creative-development and digital-studio websites: distinctive, technically sophisticated, visually memorable, fast, and intentional.

https://kander.ca/ is an important reference for quality, restraint, spatial composition, interactive storytelling, motion, and use of unusual visual elements.

Treat references as inspiration and research material, never as templates to reproduce.

Do not copy another site's branding, assets, layout, visual identity, typography, illustrations, or signature interactions.

The finished site must have an original RACCN Code identity.

## Brand hierarchy

RACCN / RACCN Code is the primary visible identity.

Do not design the homepage around the owner's full name.

The owner's name may appear where contextually appropriate, but it must not become a dominant oversized hero treatment.

The site should lead with ideas, work, engineering ability, visual identity, and interaction rather than conventional personal-portfolio presentation.

## Working principles

Before making substantial design changes:

* inspect the repository thoroughly
* understand the existing frontend and backend architecture
* run the existing project locally
* inspect the current website in a browser
* understand existing routes, content, functionality, data dependencies, and assets
* inspect the reference sites in the browser
* establish a visual direction before implementation

Preserve working functionality unless there is a strong reason to change it.

Do not blindly preserve existing UI simply because it already exists.

Do not blindly rewrite architecture simply because a redesign is being performed.

Make architectural decisions based on the current repository.

## Visual standard

Aim for:

premium
minimal
editorial
computational
precise
experimental
immersive
highly custom

Avoid generic AI-generated website patterns.

In particular avoid relying on:

generic SaaS card grids
large collections of rounded cards
gratuitous glassmorphism
constant gradients
floating technology badges
decorative particle fields
excessive glow
unnecessary pills
overly animated interfaces
template-like developer portfolio layouts

Prefer one strong idea over many weak effects.

Each major viewport or section should have a clear visual hierarchy and a dominant purpose.

Whitespace is a design tool.

Typography, composition, imagery, interactive behavior, and motion should work as one system.

## Interactive graphics

The redesign should explore whether custom 3D, procedural graphics, generative geometry, WebGL, shaders, SVG, canvas, or another visual technique could become part of RACCN Code's identity.

Do not assume a particular library or rendering technology before inspecting the project.

A signature interactive visual should have a conceptual purpose and participate in the experience.

Do not add 3D merely to demonstrate that 3D is possible.

Prefer a small number of memorable interactive moments over many unrelated effects.

## Motion

Motion should support hierarchy, atmosphere, storytelling, navigation, or interaction feedback.

Avoid motion that exists only because an element can be animated.

Prefer coherent motion language across the site.

Nothing important should become difficult to read or use because of animation.

Respect prefers-reduced-motion.

## Performance

Visual ambition must not compromise usability.

Treat performance as part of the design.

Monitor runtime cost, bundle growth, loading behavior, media weight, mobile behavior, layout stability, and interactive responsiveness throughout development.

Optimize or replace unnecessarily heavy assets when appropriate.

Use progressive enhancement and graceful fallbacks for expensive visual effects.

## Responsive design

Mobile is not simply a smaller desktop layout.

Reconsider interactions, compositions, density, and expensive effects for smaller screens.

The identity and quality should survive even when 3D or advanced effects need to be simplified.

## Accessibility

Maintain semantic HTML, keyboard usability, meaningful focus states, sufficient contrast, and reduced-motion behavior.

Decorative graphics must not interfere with access to content.

## Development workflow

Work on a dedicated redesign branch.

Do not deploy.

Do not push to production/main unless explicitly asked.

Keep a local development version available while working.

After substantial visual work, inspect the real result in a browser rather than judging only from source code.

Use screenshots and browser testing to identify visual problems.

Test major breakpoints and interaction states.

Run the production build and relevant checks before considering work complete.

## Decision making

Do not treat existing code, this document, or reference websites as unquestionable specifications.

Use professional judgment.

If the current information architecture, component architecture, visual hierarchy, interaction model, content density, or technology choices weaken the result, identify the issue and propose a better approach.

The goal is not to preserve the current implementation.

The goal is to create the strongest possible RACCN Code experience while preserving valuable functionality and content.
